The research followed a structured three-phase methodology, progressively advancing from foundational exploration through RAG-enhanced implementation to advanced agentic approaches. Each phase employed systematic experimentation with controlled variables, comprehensive documentation, and iterative refinement based on empirical evaluation of generated outputs.

**Phase 1: Foundational Question Generation (Week 1)**

The initial phase established baseline capabilities through direct Large Language Model integration without retrieval augmentation. The implementation utilized LangChain framework for LLM orchestration, integrating with Ollama for local model deployment (Llama 3.1 8B) and LM Studio for cloud-based model access (DeepSeek-R1, Mistral 7B). Comprehensive prompt engineering developed templates instructing models to generate examination-quality questions with detailed rubrics and ideal answers in structured JSON format.

The system generated 30 Operating Systems questions with 20 student response variations per question, totaling 600+ diverse responses spanning correct, partially correct, and incorrect categories. Robust JSON parsing with error handling addressed common LLM output inconsistencies including escaped characters and malformed structures. A critical innovation involved dual evaluation strategies: clarification-based evaluation adopting lenient interpretive approaches recognizing partial understanding, and target-guided evaluation providing strict criterion-referenced assessment directly comparing responses against rubrics.

**Phase 2: RAG-Enhanced Question Generation (Week 2)**

The second phase implemented comprehensive Retrieval-Augmented Generation architectures to ground question generation in specific educational materials. Document processing pipelines employed LangChain's UnstructuredPDFLoader with "elements" mode for structured extraction, filtering pages 27-44 of Cryptography and Network Security textbooks while retaining only narrative text, titles, and instructional content.

Multiple text chunking strategies were systematically evaluated. RecursiveCharacterTextSplitter implemented baseline chunking with 400-character chunks and 100-character overlap. Custom SentenceSplitter using NLTK tokenization grouped 5 sentences per chunk with 1-sentence overlap for natural linguistic boundaries. Advanced SemanticChunker from LangChain Experimental employed gradient-based breakpoint detection (threshold 90.0) with 2-sentence buffer and 300-character minimum chunk size, preserving conceptual coherence superior to arbitrary character splitting.

Vector database implementations included FAISS for efficient similarity search with local persistence and ChromaDB for scalable storage with metadata support. Embedding models tested included HuggingFace all-MiniLM-L6-v2 (384 dimensions, fast inference) and Qwen3-Embedding-0.6B (higher dimensionality, improved semantic understanding). Multiple retrieval strategies were deployed: standard vector similarity using cosine distance (k=3-5), HyDE (Hypothetical Document Embeddings) generating 5 intermediary questions per topic retrieving k=4 chunks per question, and hybrid approaches combining multiple methods with reranking.

The question generation prompt incorporated retrieved context, instructing LLMs to generate questions strictly based on provided material, dramatically reducing hallucination. Extensive datasets were produced with systematic naming conventions indicating model, temperature, chapter, version, and configuration (e.g., "llama3_1_8b_temp0_3_chapter1_v3_hyde_para_chunking_k_per_q_4num_hyde_qs_5.json"), enabling precise experimental tracking across 11+ configuration variations.

**Phase 3: Advanced Agentic RAG (Week 3)**

The final phase explored agentic approaches incorporating autonomous reasoning loops. The architecture implemented four core components: Query Planner/Router decomposing queries into sub-questions, Tool Chest providing specialized retrieval and search capabilities, Reasoning Loop executing iterative plan-observe-decide cycles using ReAct (Reasoning + Acting) pattern, and Synthesizer aggregating multi-source information into coherent outputs.

Enhanced document processing extended to Software Engineering textbooks with page-specific filtering (pages 1-28 for Chapter 1) and metadata-aware processing. Advanced semantic chunking with Qwen3-Embedding-0.6B employed gradient breakpoint detection with adaptive buffer sizing and minimum chunk constraints preventing over-fragmentation. Question formats introduced explicit delimiter markers ("Question N Start"/"Question N End") enabling robust parsing of complex multi-question outputs.

Comprehensive comparative analysis documented in six PDF reports systematically evaluated configuration impacts on question quality, retrieval accuracy, generation consistency, and computational efficiency, providing evidence-based recommendations for optimal system configuration.

**Tools and Technologies**

Primary frameworks included LangChain (orchestration), LangChain Community (document loaders, vector stores), LangChain Experimental (semantic chunking), and LangChain integrations for Google GenAI, HuggingFace, Ollama, and OpenAI-compatible APIs. Vector stores comprised FAISS and ChromaDB. Document processing employed PyPDF, UnstructuredPDFLoader, and NLTK. Data handling utilized Pandas for analysis and Excel export. Development environments included Jupyter Notebooks for interactive experimentation and VS Code for production code. Model deployment spanned Ollama (local), LM Studio (local with OpenAI API), and Together AI (cloud).
